**Never go dark**: `cache.SetAll()` is only called on success, and it refuses an empty channel list or EPG so a bad payload cannot wipe the last good snapshot. A failed refresh logs an error and serves the previous cache until the next retry. `SetAll` also invalidates lazily-cached per-tuner M3Us.

**JWT lifetime controls** (auth/session.go): `tokenRefreshMargin = 1h`, `maxTokenAge = 2h`. `EnsureFresh` (called on every M3U request and by the scheduler) forces re-auth if the token is within the margin of expiry *or* if it was issued more than `maxTokenAge` ago. Handing a playlist out does not extend that age. 401s from the stitcher are intentionally not retried inside RetryClient; the per-request refresh in server.go is the mitigation. Boot credentials are redacted from errors and logs.

**M3U path**: On each playlist request the server calls `EnsureFresh` then `Credentials()` (one lock: token + stitcherParams + `tokenGen`). The M3U string is rebuilt only when `tokenGen` or channel data changes; otherwise the cached string is served. A playlist is cached only if the channel generation it was built from is still current. The scheduler does **not** pre-build M3Us — only channels + XMLTV. A tuner re-auth failure does not skip the guide update.

**EPG fetch**: `GUIDE_HOURS` (default 24, max 72) is fetched as consecutive 6-hour windows, at most 4 at a time, and merged (see `pluto.FetchChannels` / `WindowsForHours`). A non-positive hour count still means 24 hours. Overlapping programmes are deduped and channel order is a stable sort. One failed window fails the refresh; the previous cache stays.

**Goroutine topology**: main context → HTTP server goroutine + initial sign-in goroutine + scheduler goroutine + an optional TV Everywhere refresh goroutine. The listener starts before sign-in finishes. Playlist requests return 503 without calling `EnsureFresh` until that first attempt finishes (success or failure); after `ReleaseAuth`, a failed sign-in is retried on the next playlist request. The guide does not wait on sign-in. The session mutex serializes boot so the scheduler and the initial sign-in do not boot the same tuner twice. SIGTERM cancels the context (including in-flight startup auth), stops the scheduler and the TVE refresh, then drains the HTTP server with a 30s timeout. Config or device-id failures still exit before listen. An authentication failure does not.

**Access gate** (`server.gate`): an empty `ACCESS_TOKEN` leaves every route open. When it is set, Pluto playlists (`/tuner-N-playlist.m3u`, `/tunerN/channels.m3u`, `/tunerN/m3u`), the EPG (`/epg.xml`, `/xmltv.xml`), and TV Everywhere paths from `tve.ProtectedPath` (`/tve/{id}.m3u`, `/tve/{id}.xml`, `/tve/{source}/{channel}/stream`, `/tve/directv`, `/tve/directv/code`, `/tve/directv/activate`, `/tve/directv/import`) require it. `?token=` and a single `/t/<token>/` prefix both match, and a valid prefix is stripped once before the handler runs. A `/t/` prefix that does not match is 401 even for a path that is otherwise open. `/health`, `/metrics`, `/status`, and `/` stay open. The token is not logged. `BIND_ADDR` is a host with no port; `ListenAddr` joins it to `PORT`.

**TV Everywhere** (`internal/tve`, `internal/source`): off unless `TVE_SOURCES` is set. Each enabled source is its own M3U and XMLTV under `/tve/{id}.m3u` and `/tve/{id}.xml`, plus `/tve/all.*` when `TVE_COMBINED` is on (default). DirecTV is the only provider. `DIRECTV_PASSWORD` is never logged and is not a field in `TVE_SESSION_FILE` (atomic temp file, mode 0600, same pattern as device ids). The file may hold an Adobe authn token and, after a successful browser sign-in, the Adobe client id, client secret, device id, fingerprint, and access token that the authn is bound to. While browser sign-in is in progress it also holds the regcode. Those are not logged, and `/status` does not include the activation URL or the code. Authn expiry is `simpleTokenExpires` (calendar time, often with `GMT` or `_GMT`, or a unix timestamp). A missing parse used to store now+12h; that stand-in is gone. The scheduler refreshes the Adobe client access token with the stored client credentials before `expires_in` (fallback 6h) and backs off from 1 minute to 1 hour on failure. That refresh does not extend the MVPD authn, and it does not register a new client or device. A session file written before the client identity was kept needs one more browser sign-in before headless refresh can run. WARN once when the authn is within 24h, within 1h, and when it has expired. `/status` `renewal` is `client`, `retrying`, or `needs_browser`. Browser sign-in (`POST /tve/directv/activate`, then poll) is the reliable DirecTV path: Adobe's redirect returns to the network site, so Pluto polls the regcode. Token or cookie paste is `POST /tve/directv/import`. Scripted ForgeRock login is only a fallback when A+E or Warner is enabled and no authn token is stored. It is not the renewer. A paused ForgeRock challenge is resumed at `POST /tve/directv/code`; refresh must not start a second login while one is pending or while a browser activation is outstanding. A failed sign-in or guide fetch keeps the previous programmes. A guide body that is not JSON is logged with status, content type, and a short snippet. A source that returns zero programmes is logged, and the previous programmes stay.
